# XL9555 Usage Guide

## Overview

This project provides an XL9555 application layer for TC387.
It includes:

- I2C address scan and initialization
- Key/switch input read
- LED and LoRa output control
- Optional self-test API (`xl9555_app_test`)

## Quick Start

In startup code, call:

```c
Key_Init(); // internally calls xl9555_app_init()
```

Recommended `core0_main` flow:

```c
int core0_main(void)
{
    disable_Watchdog();
    interrupt_global_enable(0);
    clock_init();
    debug_init();
    Key_Init();

    cpu_wait_event_ready();
    while (TRUE)
    {
        Key_Test_Print();
        system_delay_ms(5);
    }
}
```

## Why You Still Saw Self-Test Logs

Self-test logs only come from `xl9555_app_test()`.
If logs still appear, it usually means old firmware is still running.

Now the library keeps `xl9555_app_test()` but disables it by default via:

```c
#define XL9555_APP_ENABLE_SELF_TEST  (0)
```

To enable self-test temporarily, set it to `1` in `xl9555_app.c`.

## Important Notes

- Probe logic writes polarity test values (`0x5A/0xA5`) and restores original values immediately.
- Runtime polarity configuration is forced to non-inverted (`0x0000`).
- XL9555 legal 7-bit addresses are `0x20` to `0x27`.

## Common APIs

```c
uint8_t key1 = xl9555_app_get_key(1);
uint8_t sw1  = xl9555_app_get_switch(1);

xl9555_app_led_enable(1);
xl9555_app_led_run(1);
xl9555_app_lora_set_aux(1);
xl9555_app_lora_set_mode(0);
```

## Build/Flash Reminder

After code changes, do a full rebuild and reflash.
If you only run old binary, serial output will not reflect source updates.
